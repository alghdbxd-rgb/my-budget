# أساس للاستثمار العقاري — موقع + لوحة عمل

مشروع ويب **مستقل بالكامل**: موقع تسويقي لشركة استثمار عقاري، وصفحة بحث بين العروض،
ولوحة عمل داخلية لإدارة المكتب (العروض، العقارات، نقاط البيع، بكجات العروض، القاصة،
المستثمرون، الزبائن، التقارير).

مبني بـ **HTML + CSS + JavaScript خام فقط** — بلا React، بلا أدوات بناء، وبلا `npm install`.

---

## التشغيل والتجربة

**أسهل طريقة:** افتح `index.html` بالنقر المزدوج.

**الطريقة الأفضل** (وتلزم لرفع الفيديو وتثبيت التطبيق على الهاتف)، شغّل خادماً محلياً:

```bash
cd asas-real-estate
python3 -m http.server 8000
# ثم افتح http://localhost:8000
```

| الصفحة | الرابط | الوظيفة |
|---|---|---|
| الموقع التسويقي | `index.html` | العرض التعريفي، الخدمات، العروض المميّزة، البكجات، ونموذج طلب الزبون |
| العروض | `offers.html` | البحث والفلترة بين كل العروض المنشورة |
| لوحة العمل | `app.html` | كل شغل المكتب الداخلي |

الصفحة تفتح مباشرة بلا تسجيل دخول (لا يوجد خادم مصادقة في هذه النسخة).

## الصور والفيديو والموقع

- **الصور**: اسحبها أو اخترها من الجهاز؛ تُضغط تلقائياً داخل المتصفح (١٤٠٠ بكسل / JPEG) قبل الحفظ، وتُعيَّن واحدة منها كغلاف.
- **الفيديو**: ارفع ملفاً من الجهاز، أو الصق رابط يوتيوب/درايف/رابط مباشر (يُعرض مضمّناً داخل العرض).
- **الموقع**: ثلاث طرق — زر «موقعي الحالي» (GPS)، أو لصق رابط خرائط جوجل (تُستخرج الإحداثيات تلقائياً)، أو كتابة الإحداثيات يدوياً. تظهر خريطة معاينة مع رابط فتح في خرائط جوجل.

---

## أين تُحفظ البيانات

- **السجلات** (عقارات، عروض، بكجات، قاصة، مستثمرون، زبائن، إعدادات): `localStorage` تحت المفتاح `asas-re-v1`.
- **ملفات الوسائط** (صور وفيديو): `IndexedDB` باسم `asas-media` — يتحمّل الملفات الكبيرة. إذا كان المتصفح لا يسمح بـ IndexedDB (مثل فتح الملف بصيغة `file://` في بعض المتصفحات) تُحفظ الصور الصغيرة في `localStorage`، والفيديو يحتاج رابطاً خارجياً.
- كل شيء محلي داخل متصفح الجهاز — **لا يوجد خادم ولا قاعدة بيانات خارجية في هذه النسخة**. صدّر نسخة احتياطية من «الإعدادات ← تصدير نسخة JSON» بين فترة وأخرى.

البيانات التجريبية (٨ عقارات، ٧ عروض، بكجان، ٣ قواصة، ٣ مستثمرين) تُزرع تلقائياً أول مرة، ويمكن تفريغها من «الإعدادات ← منطقة الخطر».

## ملاحظات للمبرمج الذي سيرفعه على سيرفر

**الرفع كما هو:** المجلد ملفات ثابتة فقط — ارفعه على أي استضافة ثابتة (Netlify / Vercel / GitHub Pages / أي Nginx). لا يحتاج بناءً ولا Node.
شرطان فقط للعمل الكامل: **HTTPS** (لتشتغل خدمة العمل بدون اتصال والتثبيت على الهاتف)، وإعادة التوجيه الطبيعية للملفات (الصفحات ملفات `.html` حقيقية، فلا يلزم أي rewrite).

**الربط بباك-إند لاحقاً:** التطبيق مفصول بطبقات، ونقطة الربط الوحيدة هي `js/store.js`:

- `load()` / `save()` هما كل ما يلمس التخزين — استبدلهما بنداءات API (أو اجعل `save()` يرسل التغييرات للسيرفر ويبقي النسخة المحلية كذاكرة مؤقتة).
- `upsert(collection, item)` و `remove(collection, id)` هما المدخل الوحيد لأي تعديل على البيانات، فيكفي توجيههما إلى `POST/PUT/DELETE`.
- شكل البيانات موصوف في دالة `seed()` بنفس الملف — وهو مطابق لما يُتوقع من جداول قاعدة البيانات:
  `properties`, `offers`, `packages`, `boxes`, `cash`, `investors`, `clients`, `settings`.
- الوسائط: `js/media.js` فيه `add()` و `url()` و `del()` — استبدل `IndexedDB` برفع الملف إلى السيرفر أو خدمة تخزين، وأرجِع رابط الملف في `url()`.
- لا يوجد أي مفتاح سري أو اعتماد داخل الكود.

**ما ينقص لنسخة إنتاج متعددة المستخدمين:** تسجيل دخول وصلاحيات (مدير / مسوّق / محاسب)، وسجل تدقيق للحركات المالية، ونسخ احتياطي على السيرفر.

## تفاصيل صغيرة تفرق بالاستعمال

- كل حقول الأرقام تقبل الأرقام العربية (٠١٢٣٤٥٦٧٨٩) وتحوّلها تلقائياً.
- كل عرض له كود قصير (`ض-٢٠٠١`) للاستعمال بالهاتف، وزر **نسخ تفاصيل العرض** يجهّز رسالة واتساب كاملة بالسعر والمساحة ورابط الموقع.
- رابط مباشر لأي عرض: `offers.html?o=ض-2001`، ورابط بحث جاهز: `offers.html?kind=sale&gov=baghdad&type=house`.
- تسجيل صفقة من داخل العرض يغلق العرض، يحوّل حالة العقار إلى «مباع/مؤجّر»، ويفتح لك مباشرة قيد العمولة في القاصة.
- وضع ليلي بزر واحد، والتطبيق يشتغل بدون اتصال بعد أول زيارة.
