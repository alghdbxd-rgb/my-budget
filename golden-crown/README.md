# التاج الذهبي — نسخة معاينة محلية (Golden Crown)

هذا مجلد مستقل داخل نفس المستودع، ولا علاقة له بتطبيق الميزانية (`my-budget`) في الجذر.

تطبيق React (Vite + Tailwind) لمعاينة واجهات منصة "التاج الذهبي" لاستشارات طب
الأسنان عن بُعد، بناءً على وثيقة `BUILDSPECGoldenCrown.md`. **لا يتصل بأي خادم
أو قاعدة بيانات حقيقية** — كل البيانات (المرضى، الأطباء، الاستشارات، الأكواد،
الحركات المالية...) محفوظة محلياً في `localStorage` داخل متصفحك فقط، ليتسنى
لك تصفح الواجهات وتجربتها والتعديل عليها قبل اعتمادها ورفعها فعلياً.

## التشغيل محلياً

```bash
cd golden-crown
npm install
npm run dev
```

ثم افتح الرابط الذي يظهر (عادة `http://localhost:5174`). للبناء الإنتاجي:

```bash
npm run build && npm run preview
```

## كيفية التصفح

- الصفحة الرئيسية `/` هي الموقع التسويقي (F-P... / قسم 3.6 من المواصفات).
- زر دائري ذهبي عائم أسفل يسار الشاشة (🔲) يفتح "أداة معاينة" للتنقّل الفوري
  بين: الموقع التسويقي، تطبيق المريض، بوابة الطبيب، لوحة المشرف، لوحة الإدارة
  — ومن نفس الأداة يمكن **إعادة تهيئة كل البيانات التجريبية** من الصفر.
- **تسجيل دخول المريض**: أي رقم موبايل عراقي (مثال `07701234567`) + رمز
  التحقق التجريبي `1234` (لا يوجد SMS فعلي).
- **دخول الطبيب/المشرف/الإدارة**: بما أنه لا يوجد خادم مصادقة حقيقي، بوابة
  الطبيب تعرض قائمة حسابات تجريبية لاختيار الهوية، بينما المشرف والإدارة
  دخول مباشر (هوية واحدة افتراضية لكل منهما).
- كل الأدوار تشترك في نفس قاعدة البيانات المحلية، فتجربة كاملة ممكنة: أنشئ
  استشارة كمريض ← بدّل لدور الطبيب وأجب عليها ← ارجع للمريض وشاهد التقرير
  جاهزاً ← اذهب للإدارة واصرف الكود وشاهد الحركة المالية تتحدث فوراً.

## ما هو مبني، وبأي عمق

تمت تغطية أغلب عناصر "نطاق البناء الآن" في المواصفات (قسم 10) بشكل **شامل
لكن سطحي** حسب طلب العميل — تدفقات كاملة وقابلة للاستخدام، لكن دون تعمّق في
كل تفصيلة تحقق أو حالة استثنائية:

- **المريض**: الرئيسية، OTP، استبيان 4 شاشات (مع Auto-save فعلي ومخطط أسنان
  تفاعلي)، دفع (زين كاش/آسيا حوالة — محاكاة)، شاشة حالة الطلب، تقرير PDF
  عربي RTL (عبر طباعة المتصفح)، توجيه لأقرب الأطباء مع حجز موعد، ملف المريض.
- **الطبيب**: بروفايل، جدول أوقات، صندوق حالات، شاشة كتابة استشارة مع قوالب
  جاهزة، لوحة حسابات.
- **المشرف**: طابور الاستشارات مع تمييز الحالات الطارئة والمتأخرة، إعادة
  توجيه لطبيب آخر، مراجعة جودة الردود ومعالجة الشكاوى.
- **الإدارة**: إحصائيات، اعتماد/تعطيل الأطباء، الحركات المالية + أداة صرف
  الأكواد، إدارة نصوص المحتوى والتنبيه القانوني، الإعدادات (عدّاد المجاني،
  الرسم، مدة رد الطبيب، حد التصعيد)، سجل التدقيق.
- **محرك التوجيه والتصعيد** (`src/lib/engine.js`): مطابقة تخصص + مسافة
  جغرافية (Haversine بين إحداثيات وهمية للمحافظات والعيادات) + توزيع حمل
  عادل، وتصعيد تلقائي عند اجتماع (ألم فوق حد + تورّم + حرارة) — القيم قابلة
  للتعديل من لوحة الإدارة.

## بنود مؤجَّلة أو بحاجة مدخلات حقيقية (قسم 11 من المواصفات)

هذه النقاط **لا يمكن** لأي نسخة محلية بلا خادم أن تحلّها، وتبقى معلّقة حتى
تصل المدخلات المطلوبة من العميل/الطرف الطبي:

- ربط فعلي بـ ERPNext والـ REST API الحقيقي بدلاً من `localStorage`.
- بوابات دفع حقيقية (زين كاش / آسيا حوالة)، ومزوّد SMS فعلي لرموز OTP.
- خدمة خرائط حقيقية (حالياً نص "عنوان + مسافة تقريبية" فقط بدل خارطة تفاعلية).
- توليد PDF فعلي من الخادم (حالياً نعتمد طباعة المتصفح — وهي كافية لإثبات
  اتصال الحروف العربي واتجاه RTL مبكراً كما تطلب المواصفات، لكنها ليست
  الحل الإنتاجي النهائي).
- نص التنبيه الطبي/القانوني النهائي المعتمد (المعروض الآن نص تجريبي واضح
  المصدر ومعلَّم كمؤقت).
- الأرقام الفعلية: رسم الاستشارة، نسب توزيع الأرباح بين الطبيب/العيادة/المنصة،
  مدة رد الطبيب، حدود التصعيد الدقيقة — القيم الحالية افتراضية للمعاينة فقط
  وقابلة للتعديل فوراً من لوحة الإدارة (`/a/settings`).
- سياسة الاحتفاظ بالبيانات وحق الحذف.
- موديولات المرحلة الثانية (اجتماعات فيديو، اشتراكات معلنين، دورات، توظيف)
  — تركت كنقاط توسعة ظاهرة في الموقع التسويقي فقط بعلامة "قريباً".

## الخطوة التالية

بعد المراجعة والتعديل على الواجهات هنا محلياً، الخطوة التالية هي ربط هذه
الواجهات بخادم ERPNext حقيقي (استبدال `src/context/AppContext.jsx` و
`src/lib/db.js` بطبقة اتصال REST API) وتزويد بيانات الاعتماد الحقيقية
المذكورة أعلاه، ثم النشر (deploy) والتسليم.
