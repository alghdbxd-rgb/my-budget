# ترحيل كشف صرفيات مشروع من Excel إلى ERPNext

دليل عملي لتحويل "كشف حساب مشروع" المكتوب في Excel (وارد + أقسام صرف) إلى
قيود يومية داخل ERPNext، باستخدام `tools/xlsx_to_erpnext.py`.

## أين تذهب البيانات داخل النظام

| البيان في الاكسل | الوجهة في ERPNext |
|---|---|
| كل سطر وارد أو صرف | **قيد يومية** (Journal Entry) |
| أقسام الصرف (تشغيلية، مقاولين، رواتب، …) | **حساب كلفة** لكل قسم + **مركز كلفة** لكل قسم |
| المشروع / المجمع | حقل **Project** على كل سطر قيد |
| مصادر التمويل (الشركاء والممولين) | **حساب جارٍ** لكل ممول تحت المطلوبات |
| النقد | حساب النقد القائم في شجرة الحسابات |
| المقاولون | **موردون** (Supplier) عند الحاجة لكشف حساب لكل مقاول |

القاعدة: لا تُرحَّل المجاميع، تُرحَّل الحركات. المجاميع تصير تقارير يحسبها النظام.

## الترتيب الإلزامي للاستيراد

الحقول مرتبطة ببعضها، فأي مستند يشير إلى آخر يتطلب وجود الآخر قبله:

1. **مركز الكلفة** (Cost Center) — `erpnext-01-cost-centers.csv`
2. **الحسابات** (Account) — `erpnext-02-accounts.csv`
3. **المشروع** (Project) — يُنشأ يدوياً باسم واحد يطابق ما في ملف القيود
4. **الموردون** (Supplier) — عند اعتماد كشوف حساب المقاولين
5. **قيود اليومية** (Journal Entry) — `erpnext-03-journal-entries-ready.csv`

## خطوات الاستيراد في الواجهة

1. ابحث عن `Data Import` ← **جديد**
2. اختر نوع المستند، ثم **Insert New Records**
3. **نزّل القالب** من نفس الشاشة وقارن رؤوس أعمدته بالملف المُولَّد — تسميات
   الأعمدة تختلف بين النسخ وبين المواقع المعرّبة، والقالب المنزَّل هو المرجع
4. ارفع الملف، وراجع **المعاينة والأخطاء** قبل التنفيذ
5. **Start Import**، ثم طابق المجاميع مع الملف الأصلي قبل الانتقال للمرحلة التالية

## قبل أي استيراد

- خذ **نسخة احتياطية**، وجرّب على موقع تجريبي أولاً.
- استورد على دفعات صغيرة وتحقق بعد كل دفعة.
- اترك القيود **مسوّدة** حتى تُطابق الأرصدة، ثم اعتمدها دفعة واحدة.

## ما تفعله الأداة

```bash
python3 tools/xlsx_to_erpnext.py <ملف.xlsx> <config.json> <مجلد الإخراج>
```

* تستبعد صفوف المجاميع (SUM) وتقارن المحسوب بالمعلن في الملف.
* تعالج التواريخ المختلطة: نص `يوم/شهر/سنة` مقابل خلايا فسّرها Excel بنظام
  `شهر/يوم`. تُحسم بالترتيب الزمني للصفوف المجاورة، وما يبقى ملتبساً يُعلَّم
  للمراجعة اليدوية ويُعزل في ملف مستقل بدل تخمينه بصمت.
* توحّد أسماء الأطراف وتفصل الوصف عن الاسم.
* ترصد الازدواج المحتمل بين صف السلفة وصفوف الصرف المرتبطة بها.
* تُخرج: بيانات منظفة (xlsx + csv)، كشف الأطراف، وملفات Data Import جاهزة،
  مقسّمة إلى `ready` و`review-dates` و`missing-dates`.

ملف `config.json` يصف الشيتات وأرقام الأعمدة وقواعد توحيد الأسماء وإعدادات
ERPNext (الشركة، الرمز، المشروع، الحسابات، مراكز الكلفة) — يُكتب لكل ملف على حدة
ولا يُخزَّن داخل المستودع لأنه يحمل بيانات العميل.
